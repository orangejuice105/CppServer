| 检查 | 实测结果 |
|---|---|
| 普通请求 | 完整请求头逐字节打印，随后关闭连接 |
| 请求行分段 | 第一段不打印、不关闭，补齐请求后完整打印 |
| 结束标记分段 | CRLFCRLF 的三个内部切分位置均通过 |
| 逐字节发送 | 最后一个结束标记字节到达后才打印；未假设每次发送对应一次接收 |
| 跨缓冲区 | 6000 字节请求头跨多次接收，输出完整一致 |
| 恰好达到上限 | 包含结束标记共 8192 字节，正常打印且没有超长警告 |
| 达到上限仍未完成 | 8192 字节无结束标记，立即关闭，记录“累积数据达到上限” |
| 完整头超过上限 | 两段发送组成 8193 字节头，触发“请求头长度超出上限”分支 |
| 尾随数据 | 请求头后附带其他字节，只打印到第一个结束标记 |
| 半关闭 | 完整请求后结束发送方向，仍完整打印并关闭 |
| 提前 EOF | 未完成的请求不作为完整头打印，释放连接，后续请求正常 |
| RST | 未完成请求异常断开，记录接收失败，后续请求正常 |
| 连续连接 | 连续 40 次输出准确，正常路径 fd 数回到基线 5 |
| 排队和拒绝 | A 等待补齐，B 排队，C 被拒绝；A 补齐后依次打印 A、B |
| EINTR | 注入 accept、recv 的 EINTR 各一次，重试后输出完整，无 ERROR |
| 真实接收超时 | 不完整请求停止发送，等待约 30.11 秒后记录 WARN 并关闭，后续请求正常 |

## 验证边界

- 目前只识别头部结束标记及长度；没有解析和验证 HTTP 请求行或请求头语法。
- 尚未发送 HTTP 响应、处理请求体、支持 keep-alive；没有执行发送超时检查。
- 接收超时仍针对单次阻塞接收，不是整个请求的总时限。
- EINTR 检查使用返回值注入，不代表真实信号投递测试。
- fd 回收检查覆盖本轮正常重复连接路径，不是所有异常路径和长期压测证明。

上述尚未实现的功能属于后续学习内容，不能将本次通过理解成完整 HTTP 服务器验收。
